## Deep Web Search Per Project (Mandatory Standard)

For any task that involves **live or volatile facts** — current pricing, product/feature changes, client-specific configuration, regulator or vendor updates, or current best practice — the agent MUST perform a **deep web search scoped to the project** BEFORE finalizing the deliverable. Do not rely solely on cached SOP/Playbook knowledge.
- **Tool:** the CRW crawler (`crw_scrape` for pages, `crw_map` for site discovery). Use `crw_map` on the vendor/authority domain, then `crw_scrape` the most relevant pages. Fallback: Jina via shell redirection (see Web Access standard).
- **Depth:** follow the project's key entities (vendor docs, official changelogs, authoritative guides) — not a single query. Capture what changed vs the cached SOP.
- **When NOT required:** pure planning/archival deliverables where the SOP is already authoritative and the user explicitly scopes to vault-only (e.g. Knowledge Sync dry-runs).
- **Record:** note the sources checked in the deliverable (Sources section) and store a Mnemosyne memory of any material update.

## Live Web Refresh (2026-08-03)

- Microsoft Entra Conditional Access: Zero Trust Policy Engine — https://learn.microsoft.com/en-us/entra/identity/conditional-access/overview — Conditional Access is Microsoft's Zero Trust policy engine: if-then statements that enforce org policy after first-factor auth. Key signals: user/group/agent identities, IP location, device state/compliance, target application, real-time risk (ID Protection), and Defender for Cloud Apps. Decisions range from block to grant-with-controls (MFA, authentication strength, compliant/hybrid-joined device, approved client app, app protection policy). New: agent identities let Zero Trust extend to AI workloads. (verified live via CRW on 2026-08-03)
- What is Microsoft 365 Copilot? — https://learn.microsoft.com/en-us/copilot/microsoft-365/microsoft-365-copilot-overview — M365 Copilot is an AI tool that answers from the web plus organizational data the user can already access; it requires an add-on license, unlike Copilot Chat (web-only, no add-on license). Admins can build custom agents over org data sources. OpenAI and Anthropic are documented subprocessors inside M365 Copilot. (verified live via CRW on 2026-08-03)
- Why do I need Microsoft Defender for Office 365? — https://learn.microsoft.com/en-us/microsoft-365/security/office-365-security/overview — Defender for Office 365 is the primary email/collaboration security solution. The "protection ladder": built-in EOP security (all cloud mailboxes) -> Plan 1 (E3/G3, Business Premium) -> Plan 2 (A5/E5/G5), plus add-on. Plan 2 adds Safe Links, Safe Attachments, and richer threat investigation. A 90-day Plan 2 trial is available. (verified live via CRW on 2026-08-03)

### Skill improvements adopted

1. **Frame every Entra access-control question as Conditional Access, not per-app settings.** Lead with the Zero Trust if-then model: first-factor auth happens first, then CA enforces controls. Map the customer's real signals (user/group/agent, IP, device compliance, app, sign-in risk) to a grant decision, and remember agent identities now fall under CA for AI workloads.
2. **Disambiguate M365 Copilot vs Copilot Chat before recommending license or data-scope changes.** M365 Copilot (add-on license, org data + web) is distinct from Copilot Chat (no add-on, web + user-supplied org data). When scoping Copilot rollouts, note OpenAI/Anthropic as subprocessors and point to the privacy article for the permissions model.
3. **Situate email security as a protection ladder, not a single product.** Always name the tier: built-in EOP for everyone, Defender for Office 365 Plan 1 for E3/Business Premium, Plan 2 for E5. Recommend Plan 2 Safe Links/Safe Attachments for phishing/BEC defense and offer the 90-day trial to evaluate.

## Live Web Refresh (2026-08-05)

- Plan for mandatory Microsoft Entra multifactor authentication (MFA) — https://learn.microsoft.com/en-us/entra/identity/authentication/concept-mandatory-multifactor-authentication — Phase 1 (Oct 2024) covers Azure portal / Entra admin center / Intune admin center, and M365 admin center from Feb 2025. Phase 2 started **October 1, 2025** and extends MFA enforcement to Azure CLI (04b07795-8ddb-461a-bbee-02f9e1bf7b46), Azure PowerShell (1950a258-227b-4e31-a9cf-717495945fc2), Azure mobile app, IaC tools, REST control-plane and SDK — for Create/Update/Delete only; Read is exempt. Break-glass/emergency accounts are NOT exempt and should move to passkey (FIDO2) or certificate-based auth. User-based service accounts should migrate to workload identities. (verified live via CRW on 2026-08-05)
- Data, Privacy, and Security for Microsoft 365 Copilot — https://learn.microsoft.com/en-us/copilot/microsoft-365/microsoft-365-copilot-privacy — Copilot only surfaces content the user already has at least view permission to via Microsoft Graph, so SharePoint/Teams oversharing is the real risk surface, not the LLM. Prompts, responses and Graph-retrieved data are never used to train foundation LLMs. Built-in protections: harmful content blocking, protected material detection, and prompt-injection/jailbreak blocking. Anthropic and OpenAI now appear as documented **subprocessors** inside M365 Copilot experiences — a new compliance/DPIA line item. GDPR + EU Data Boundary commitments extend to M365 Copilot Search. (verified live via CRW on 2026-08-05)
- Deprecation of Basic authentication in Exchange Online — https://learn.microsoft.com/en-us/exchange/clients-and-mobile-in-exchange-online/deprecation-of-basic-authentication-exchange-online — Basic auth is now permanently disabled in ALL tenants; neither admins nor Microsoft Support can re-enable it. Affected: EAS, POP, IMAP, Remote PowerShell, EWS, OAB, Autodiscover, Outlook for Windows/Mac. SMTP AUTH was disabled in tenants with no usage. App passwords are also dead as a side effect. Remediation is always "move to OAuth 2.0 modern auth", never "request an exception". (verified live via CRW on 2026-08-05)

### Skill improvements adopted

1. **Lead identity remediation with the Phase 2 automation blast radius, not the portal.** When triaging an M365/Entra MFA question, immediately ask what runs unattended: Azure CLI/PowerShell scripts, IaC pipelines, REST control-plane callers, and break-glass accounts. Since 1 Oct 2025 these all fail on write operations without MFA. Standard fix path: user-based service account -> workload identity / managed identity; break-glass -> FIDO2 passkey or CBA; leave read-only automation alone (reads are exempt).
2. **Treat M365 Copilot risk as a permissions and subprocessor problem, not a model problem.** Default answer to "is Copilot leaking data?" is a SharePoint/Teams oversharing audit plus sensitivity labels — Copilot honors existing permissions and does not train on tenant data. Separately, flag Anthropic/OpenAI as named subprocessors when a customer's DPIA, GDPR record, or EU Data Boundary review comes up.
3. **Never propose re-enabling Basic auth in Exchange Online.** It is irreversible tenant-wide. Any legacy POP/IMAP/EWS/RPS/app-password dependency gets an OAuth 2.0 migration plan (or Graph API replacement for EWS), not a support ticket.

Separately, flag Anthropic/OpenAI as named subprocessors when a customer's DPIA, GDPR record, or EU Data Boundary review comes up. Note: Anthropic models excluded from EU Data Boundary.

3. **Never propose re-enabling Basic auth in Exchange Online.** It is irreversible tenant-wide. Any legacy POP/IMAP/EWS/RPS/app-password dependency gets an OAuth 2.0 migration plan (or Graph API replacement for EWS), not a support ticket.

4. **Frame every Entra access-control question as Conditional Access, not per-app settings.** Lead with the Zero Trust if-then model: first-factor auth happens first, then CA enforces controls. Map the customer's real signals (user/group/agent, IP, device compliance, app, sign-in risk) to a grant decision, and remember agent identities now fall under CA for AI workloads.

5. **Situate email security as a protection ladder, not a single product.** Always name the tier: built-in EOP for everyone, Defender for Office 365 Plan 1 for E3/Business Premium, Plan 2 for E5. Recommend Plan 2 Safe Links/Safe Attachments for phishing/BEC defense and offer the 90-day trial to evaluate.

6. **Use Secure Score via Defender Unified RBAC as the posture KPI.** Create custom roles with Exposure Management permissions rather than relying on Entra global roles. This aligns with least-privilege and the new Defender XDR permission model.

7. **For migration planning, distinguish Migration Orchestrator (multi-workload cross-tenant) from Migration Manager (external sources → SPO/ODB) from SPMT (SharePoint Server → SPO).** Match tool to scenario: M&A/divestiture → Orchestrator; Google Workspace/Dropbox/file shares → Migration Manager; on-prem SharePoint → SPMT.

8. **EXO PowerShell V3 is REST API-first.** Use Get-EXO* cmdlets for bulk operations; app-only cert auth for unattended scripts; managed identities for Azure-hosted automation. Get-ConnectionInformation for connection inspection. Don't use Invoke-Command (not supported in REST API).

9. **Workload identities replace user-based service accounts everywhere.** Managed identities for Azure; workload identity federation for GitHub Actions/Kubernetes/external CI/CD; Entra Agent ID for AI agents with enforced sponsorship and lifecycle governance.

10. **Microsoft Purview DSPM (preview) is the new AI data security posture control.** Unifies Purview solutions for visibility across traditional apps and AI apps/agents. Include in any AI readiness or Copilot rollout assessment.
